Android NDK 28 is removed from the GitHub runner images

When
2026-10-01
Status
In effect
Platform
GitHub Actions
Who
Android apps that pin NDK 28.2.13676358 and are built on a GitHub-hosted image without it (Ubuntu and Windows since October 2026; the macOS images still had it on 2026-11-24). Gradle can install it during the build when its license is accepted; otherwise the build can fail.
What happens
Warning only. Only workflows that explicitly use NDK 28 (via ndkVersion or an NDK 28 path) are affected once it's removed.

How to fix

Bare React Native

For a React Native app that keeps its android and ios folders in the repository, Expo modules or not. Native changes go into those folders.

  • Gradle (native Android): Install the NDK in the workflow before the build (sdkmanager --install "ndk;28.2.13676358"), or set ndkVersion to a version on the image.

Native Android and iOS

For an app built with Gradle or Xcode alone.

  • Gradle (native Android): Install the NDK in the workflow before the build (sdkmanager --install "ndk;28.2.13676358"), or set ndkVersion to a version on the image.
